Portal → Collector · command dispatch sequence

An operator clicks “Power off” on a device. The round trip is sub-second:

  1. The portal sends POST /api/v1/devices/{id}/command. portalauth resolves the Principal, and the command.device permission gates the call.
  2. commands.Submit inserts a pending row, RLS-scoped to the caller's tenant, and fires NOTIFY cmd_pending.
  3. The Collector's held /bridge/poll (LISTEN, up to 25 s) wakes. bridgeauth verifies the HMAC, and ClaimPending marks the row in_progress.
  4. The Collector invokes the device adapter (sony_bravia, tesira, poly_videoos…) and captures the result or error.
  5. The Collector posts to /bridge/commands/{id}/result. commands.Complete sets succeeded or failed and fires NOTIFY cmd_done.
  6. The portal handler, waiting in WaitForTerminalNotified, wakes on the notify, with 200 ms polling as a fallback. It writes an audit row and responds.
  7. If the Collector drops mid-execution, commands.Sweeper requeues the claim after 5 min. After 3 claims, the command fails with the reason bridge_timeout.

Portal auth chain

  • Entra ID (customer): OIDC code flow, then just-in-time provisioning, then a local session is minted.
  • Entra ID (partner): the partner's tenant gives a partner Principal, which uses X-Customer-Scope to act for a customer.
  • Local: a bcrypt password creates a user_sessions row and an av_ token.
  • Magic link: helpdesk-issued, single use, stored as SHA-256.

Public API auth

  • The token format is avb_<prefix>_<secret>.
  • Tokens are stored as SHA-256(raw). The prefix is visible; the secret cannot be recovered.
  • Scopes are fixed when the token is generated (v1: view.*).
  • last_used_at and last_used_ip are updated on each call.
  • Revocation is immediate, through revoked_at.

Collector auth

  • Each Collector has its own HMAC secret, AES-GCM encrypted at rest.
  • Enrolment: the portal issues a single-use token, the installer calls /public/collectors/enroll, and the secret is returned once.
  • Every later call signs the body with HMAC-SHA256 in X-Signature.
  • Rotation is done by re-enrolment.
Legend
  • Runtime A · Collector (cyan) runs on the customer LAN.
  • Runtime B · Cloud (indigo) is one binary that hosts every route group.
  • Runtime C · Portal (magenta) is a Next.js app that calls the cloud API.
Key wire contracts
  • /ingest, /bridge/*: HMAC, Collector to cloud.
  • /api/v1: portal session tokens (av_).
  • /pub/v1: public API bearer tokens (avb_).
  • /public/*: pre-login (branding, reset, enrol, install).
Background workers
  • commands.Sweeper requeues stale claims every 30 s.
  • collectorhealth derives Collector status from heartbeats.
  • nightly runs the scheduler and the morning digest.
  • sessioncleanup sweeps expired sessions.
Isolation model
  • FORCE row-level security: policies match customer_id against app.current_customer, which is set per transaction by db.WithTenant.
  • Partner access is explicit through X-Customer-Scope and a partner Principal.
